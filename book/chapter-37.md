# Глава 37. Profiling

Профилирование — это процесс сбора данных о том, как программа использует ресурсы во время выполнения. Для WebAssembly-приложений эта задача нетривиальна: WASM-код выполняется в виртуальной машине, часто с JIT-компиляцией, а граница между WASM и хост-средой (JavaScript, браузер или серверный рантайм) создаёт дополнительные сложности. В этой главе мы рассмотрим инструменты и методы профилирования WebAssembly в 2026 году — от браузерных DevTools до системных профайлеров уровня ядра.

## DevTools 2026: анализ Flame Chart

Браузерные инструменты разработчика остаются основным средством профилирования WebAssembly в веб-среде. В 2026 году все основные браузеры предоставляют встроенную поддержку WASM-профилирования.

### Chrome DevTools

 Chrome DevTools позволяет анализировать производительность WebAssembly через вкладку Performance. При записи профиля WASM-функции отображаются в Flame Chart (пламеграфе) с именами, если модуль содержит секцию имён (Name Section). Если имена отсутствуют, функции отображаются как `wasm-function[123]` — по индексу в таблице функций.

 ### Firefox Profiler

 Firefox Profiler (доступен по адресу `profiler.firefox.com`) предоставляет схожие возможности, но с акцентом на интеграцию с экосистемой Firefox. Профили могут быть экспортированы и проанализированы с помощью `chrome://tracing`-совместимых инструментов.

 **Символизация WASM-функций.** Если у вас есть WASM-модуль с отладочной информацией (не-стрипнутый бинарник), его можно использовать для символизации уже записанного профиля Firefox. Инструмент `profiler-edit` с флагом `--symbolicate-wasm` позволяет подменить имена функций в сохранённом профиле:

 ```bash
 node profiler-edit.js -i input.json.gz \
   --symbolicate-wasm http://host/a.wasm=./a-unstripped.wasm \
   -o out.json.gz
 ```

 Этот инструмент ищет функции с именами вида `wasm-function[123]` и заменяет их на имена из секции имён указанного WASM-файла.


### Firefox Profiler

Firefox Profiler (доступен по адресу `profiler.firefox.com`) предоставляет схожие возможности, но с акцентом на интеграцию с экосистемой Firefox. Профили могут быть экспортированы и проанализированы с помощью `chrome://tracing`-совместимых инструментов .

### Анализ памяти через DevTools Protocol

Для анализа памяти WebAssembly-приложений в браузере используется DevTools Protocol (CDP). Инструменты вроде **memlab** захватывают heap-снимки V8 через CDP и анализируют утечки JavaScript-объектов, связанных с WASM-рантаймом :

- Отслеживаются объекты JS-транспортного слоя: `ClientRPC`, `ChannelStream`, `Promise`, `Generator`, замыкания `onNext` .
- Снимки кучи V8 позволяют выявлять объекты, которые удерживаются в памяти после смены маршрута или завершения жизненного цикла компонента .

## Инструменты: chrome://tracing

`chrome://tracing` (также известный как Catapult Trace Viewer) — это универсальный инструмент для визуализации трассировочных данных, поддерживающий формат Chrome JSON . Он широко используется для анализа производительности WebAssembly на уровне рантайма и браузера.

### Формат Chrome Tracing

Chrome Tracing использует JSON-формат, состоящий из событий с временными метками. Формат поддерживает:

- **Duration events** — события с началом и концом (например, выполнение функции).
- **Instant events** — события в момент времени (например, аллокация памяти).
- **Async events** — асинхронные события, связанные между собой через идентификаторы.

### Конвертация в Chrome Tracing

Профайлеры, не поддерживающие Chrome Tracing напрямую, могут генерировать данные в этом формате. Например, `traceconv` из состава Perfetto конвертирует protobuf-трассы в JSON, совместимый с `chrome://tracing` :

```bash
./traceconv json input.proto output.json
```

Perfetto также позволяет открывать трассы в `chrome://tracing` через веб-интерфейс `ui.perfetto.dev`, который запускает конвертацию внутри браузера с помощью WebAssembly .

## Профайлеры для WASM

За пределами браузера — на серверах, edge-устройствах и в IoT — доступны более мощные системные профайлеры. Wasmtime, основной WASM-рантайм от Bytecode Alliance, поддерживает интеграцию с несколькими популярными профайлерами .

### Linux perf

`perf` — стандартный профайлер для Linux. Wasmtime поддерживает два режима интеграции .

**Perfmap (простой режим).** Создаёт файл `/tmp/perf-XXXX.map`, который `perf` автоматически использует для разрешения символов :

```bash
perf record -k mono wasmtime --profile=perfmap foo.wasm
perf report --input perf.data
```

**Jitdump (расширенный режим).** Предоставляет более детальную информацию, включая привязку к исходным кодам через DWARF :

```bash
perf record -k mono wasmtime --profile=jitdump foo.wasm
perf inject --jit --input perf.data --output perf.jit.data
perf report --input perf.jit.data
```

Wasmtime генерирует файл `jit-XXXX.dump`, который затем объединяется с `perf.data` через `perf inject`. Результат позволяет аннотировать WASM-функции и видеть их ассемблерный код .

Для получения более полной информации (имена файлов, номера строк) используется флаг `-g` (debug info) при запуске Wasmtime .

### Intel VTune

VTune — популярный профайлер для x86-архитектур, доступный в коммерческой и бесплатной версиях . Wasmtime поддерживает VTune через библиотеку `ittapi` :

```bash
vtune -run-pass-thru=--no-altstack -collect hotspots target/debug/wasmtime --profile=vtune foo.wasm
```

Результаты сохраняются в директорию `r000hs/` и могут быть проанализированы через GUI или командную строку VTune .

### WACP: профилирование интеропа Python ↔ WASM

**WACP (WebAssembly-Python Profiler)** — исследовательский инструмент, разработанный для анализа производительности взаимодействия между Python и WebAssembly . Он комбинирует:

- Аппаратные счётчики производительности (PMU) через Linux-ядро.
- Sampled-based profiling для сбора данных о выполнении.
- Jitdump для разрешения символов JIT-скомпилированных WASM-функций .

WACP решает проблемы, с которыми не справляются традиционные профайлеры: недостаточная детализация анализа данных и сложность отображения символов при кросс-языковом взаимодействии .

### wasm-memprof: профилирование кучи WASM в браузере

**wasm-memprof** — библиотека для профилирования кучи WebAssembly в браузерах на движке V8 . Ключевые особенности:

- **Не требует перекомпиляции** WASM-модуля.
- **Инструментирует** функции аллокации (`malloc`, `free`, `calloc`, `realloc`, `posix_memalign`, `aligned_alloc`) через обёртку `WebAssembly`-объекта .
- **Sampling-based** — собирает стек-трейсы аллокаций с заданной частотой, снижая накладные расходы .
- **pprof-формат** — результаты сохраняются в формате pprof, который может быть визуализирован через `pprof` или Speedscope .

```javascript
import { WMProf } from "wasm-memprof";

const WebAssembly = WMProf.wrap(globalThis.WebAssembly);
const { instance } = await WebAssembly.instantiate(buffer);
instance.exports.myFunction();

const wmprof = WMProf.get(instance);
wmprof.downloadSnapshot(); // скачать pprof-файл
```

Библиотека поддерживает деманглинг имён функций (встроенный деманглер для Swift, возможность добавления своих) .

### WarpL: выявление неоптимальных инструкций в рантаймах

**WarpL** — инструмент, представленный на ICSE 2026, который использует **mutation-based inference** для диагностики проблем производительности в WASM-рантаймах . Принцип работы:

1. Создаётся мутант исходной WASM-программы, функционально идентичный, но без проблемы производительности.
2. Сравнивается машинный код оригинальной и мутировавшей программы.
3. Выделяются конкретные неоптимальные инструкции, вызывающие проблему.

WarpL выявил точные причины в 10 из 12 реальных проблем производительности в трёх популярных рантаймах, включая шесть ранее неизвестных проблем в Wasmtime .

## Поиск узких мест

Поиск узких мест (bottleneck identification) в WebAssembly-приложениях требует системного подхода.

### CPU-узкие места

Для CPU-связанных задач используется:

- **perf** с `--profile=jitdump` для детального анализа .
- **VTune** для hotspots-анализа на Intel-архитектурах .
- **WACP** для кросс-языковых сценариев (Python + WASM) .

Результаты визуализируются в Flame Chart, где ширина каждого прямоугольника пропорциональна времени выполнения функции .

### Память-узкие места

Для проблем с памятью используется:

- **wasm-memprof** для heap-профилирования в браузере .
- **memlab** для анализа утечек JavaScript-объектов, связанных с WASM .
- Анализ фрагментации линейной памяти через отслеживание `memory.grow` и аллокаций.

### Интероп-узкие места

Граница между WASM и JavaScript — частое узкое место. Для его выявления:

- Анализируйте количество переходов через границу в профиле (каждый вызов JS-функции из WASM — это событие).
- Используйте инструменты трассировки (например, Chrome Tracing) для измерения времени выполнения каждого перехода.
- WACP специально спроектирован для анализа интеропа между Python и WASM .

### Браузерное кэширование компилированного кода

В Chrome кэширование скомпилированного WASM-кода работает только с потоковыми API (`instantiateStreaming` / `compileStreaming`) . Для проверки работы кэша используется `chrome://tracing` с фильтром по событиям, связанным с кэшированием .

---

Профилирование WebAssembly в 2026 году — это многослойная задача, охватывающая браузерные DevTools (Flame Chart, heap snapshots), системные профайлеры (`perf`, VTune), специализированные инструменты (WACP, wasm-memprof) и исследовательские решения (WarpL). Ключевой принцип: выбор инструмента зависит от контекста выполнения (браузер vs сервер), типа анализируемого ресурса (CPU vs память) и уровня детализации, необходимого для диагностики. Правильно выбранный и настроенный профайлер позволяет не только найти узкое место, но и понять его первопричину, сокращая время на оптимизацию на порядки.
