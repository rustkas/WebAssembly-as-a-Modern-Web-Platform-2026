# Глава 6. WASM как второй execution layer Web Platform

WebAssembly изменил фундаментальную архитектуру веб-платформы. До его появления браузерная виртуальная машина могла загружать и исполнять только один тип кода — JavaScript . WebAssembly добавил второй исполнительный слой. Это не замена JavaScript, а параллельная среда выполнения, спроектированная для задач, где производительность и предсказуемость JavaScript достигают своих пределов .

## Концепция браузерной ОС

Веб-платформа состоит из двух частей: виртуальной машины, исполняющей код приложения, и набора Web API, предоставляющих доступ к возможностям браузера и устройства — DOM, CSSOM, WebGL, IndexedDB, Web Audio и другим . До WebAssembly виртуальная машина была однокзычной.

WebAssembly превратил браузер в мультиязычную среду исполнения. Теперь виртуальная машина загружает и исполняет два типа кода — JavaScript и WebAssembly . Они могут вызывать друг друга синхронно. WebAssembly JavaScript API оборачивает экспортированные WASM-функции в обычные JavaScript-функции, а WASM-код может импортировать и синхронно вызывать JavaScript-функции .

WASM-модули симметричны ES-модулям. Модуль — это скомпилированный браузером бинарный файл, который объявляет импорты и экспорты, как и ES-модуль . Инстанс — это модуль в паре со своим состоянием: памятью, таблицей и импортированными значениями . Эта симметрия — не случайность. WebAssembly проектировался как полноправный участник модульной экосистемы веба .

Браузер превращается в операционную систему для приложений: JavaScript остаётся языком UI и событий, WebAssembly становится языком вычислений и логики.

## JS для событий, WASM для логики и данных

Разделение ответственности между JavaScript и WebAssembly не техническое ограничение, а архитектурный паттерн. Каждая технология имеет свои сильные стороны.

JavaScript — высокоуровневый, гибкий и выразительный язык. Он динамически типизирован, не требует шага компиляции и имеет огромную экосистему фреймворков и библиотек . JavaScript идеален для работы с DOM, обработки событий, асинхронных операций и быстрого прототипирования.

WebAssembly — низкоуровневый язык, похожий на ассемблер. Его компактный бинарный формат обеспечивает производительность, близкую к нативной, и служит целью компиляции для языков с низкоуровневой моделью памяти, таких как C++ и Rust .

На практике это означает:

- **JavaScript** отвечает за взаимодействие с пользователем: клики, ввод, анимации, навигацию, загрузку данных. Он вызывает WASM-функции для тяжёлых вычислений.
- **WebAssembly** выполняет вычисления: обработку изображений, аудио, видео, криптографию, симуляции, машинное обучение. Он возвращает результаты в JavaScript для отображения.

Эта модель не нова. Разработчики игр и графических приложений десятилетиями разделяли «логику» и «представление». WebAssembly впервые сделал это разделение естественным для веба.

## Интеграция WASM в Web API

WebAssembly не существует в вакууме. Он интегрирован в веб-платформу на нескольких уровнях.

### Модель безопасности

WebAssembly использует ту же модель безопасности, что и другой веб-код. WASM-модули выполняются в безопасной песочнице и следуют политике одного источника и политике разрешений браузера . Кросс-оригинальная загрузка требует CORS, для безопасной доставки через CDN используется подресурсная целостность .

Это означает, что WASM-модуль не может получить доступ к ресурсам за пределами своей песочницы без явного разрешения. В браузере WASM-модуль имеет доступ только к своей линейной памяти. Он не может напрямую обращаться к файловой системе, сети или аппаратному обеспечению .

### JavaScript API

WebAssembly JavaScript API — это мост между двумя мирами. Он позволяет JavaScript :

- Компилировать WASM-модули;
- Выполнять рефлексию над скомпилированными модулями;
- Сохранять и извлекать скомпилированные модули из офлайн-хранилища;
- Инстанцировать модули с JavaScript-импортами;
- Вызывать экспортированные функции инстансов;
- Создавать псевдонимы для экспортированной памяти.

В будущем WASM-модули можно будет загружать как ES-модули, используя `<script type="module">` . JavaScript сможет получать, компилировать и импортировать WASM-модуль так же легко, как ES-модуль.

### Интеграция с Component Model

Инструменты вроде Jco (Bytecode Alliance) выводят интеграцию на новый уровень. Jco — это «мульти-инструмент для JS-экосистемы WebAssembly». Он может взять любой WASM-компонент (написанный на Rust, Go, Python, C, JavaScript или любом другом языке) и преобразовать его в модули core Wasm с JavaScript-склеивающим кодом, который работает в Node.js или любом браузере без нативной поддержки Component Model .

Под капотом Jco использует:
- **js-component-bindgen** — генерацию кода подъёма и опускания для каждого типа Component Model на основе WIT-контракта .
- **WASI P2 и P3 шеймы** — JavaScript-реализации WASI-интерфейсов (файловая система, HTTP, часы, случайность), позволяющие транслированным компонентам вызывать API в браузере или Node.js .

### Расширение за пределы браузера

Роль WebAssembly как второго исполнительного слоя не ограничивается браузером. С появлением WASI WebAssembly стал платформой для вычислений везде: на серверах, на edge, в IoT .

**WASI** стандартизирует системные вызовы, позволяя WASM-модулям работать в любой среде с поддержкой WASI, независимо от реальной реализации системных вызовов . Это похоже на POSIX, но для WebAssembly.

**Прокси как платформы WASM.** В облачных приложениях прокси всё чаще используются как платформы для выполнения WASM-модулей. Envoy Proxy расширил свою цепочку фильтров, чтобы вызывать и выполнять WASM-модули. Эти модули могут обеспечивать авторизацию на основе политик, фильтрацию данных, шифрование и другие меры безопасности . WASM выполняется в песочнице, что обеспечивает изоляцию от хост-системы .

## Эволюция браузеров как мультиязычных сред

Браузеры прошли путь от однокзычных сред до мультиязычных платформ.

**V8, SpiderMonkey и другие движки** теперь поддерживают не только JIT-компиляцию JavaScript, но и компиляцию WebAssembly. В mainstream-движках WASM тесно интегрирован в пайплайн JIT-компиляции, что обеспечивает производительность, близкую к нативной, при сохранении интероперабельности с JavaScript-объектами .

**Лёгкие рантаймы.** Появились лёгкие решения, такие как QJWasm — рантайм, интегрирующий WASM в QuickJS через архитектурный co-design. QJWasm вводит единую крос-рантаймовую модель памяти, согласовывающую управление временем жизни объектов в JS и WASM, и трёхканальный протокол для асинхронных вызовов . В тестах QJWasm ускорял выполнение JS-программ в 6.78 раз, а асинхронных WASM-вызовов — до 35.97 раз по сравнению с QuickJS .

**Браузер как ОС.** Проекты вроде StackBlitz с его движком WebContainers демонстрируют, куда движется веб-платформа: полноценная Node.js-среда — файловая система, пакетный менеджер, дев-сервер — работает целиком в браузерной вкладке поверх WebAssembly, без единого запроса к серверу для выполнения кода. Это стало возможным благодаря сочетанию WASI-совместимого исполнения Node.js внутри WASM-песочницы и Service Worker для перехвата сетевых запросов внутри той же вкладки. Это показывает, что WebAssembly — не просто «ускоритель», а фундамент для создания полноценных приложений в браузере.


**Node.js в песочнице.** Edge.js от Wasmer — ещё один шаг в этом направлении. Edge.js запускает Node.js-приложения в песочнице WebAssembly, сохраняя полную совместимость с Node. Системные вызовы и нативные модули изолируются через WASIX, а JS-движок (V8, JavaScriptCore или QuickJS) работает нативно . Это позволяет запускать существующие Node.js-приложения без изменений в серверлесс-среде с быстрым стартом и высокой плотностью размещения, чего нельзя достичь с контейнерами .

---

WebAssembly стал вторым исполнительным слоем веб-платформы. Он не заменил JavaScript. Вместе они образуют мультиязычную среду, где каждый язык делает то, что у него получается лучше всего. JavaScript управляет событиями и UI, WebAssembly выполняет вычисления и обрабатывает данные. Браузеры эволюционируют в операционные системы для приложений, а WebAssembly выходит за пределы браузера — на серверы, в edge, в IoT. Это не будущее. Это настоящее.
