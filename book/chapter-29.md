# Глава 29. WASM как UI Execution Layer

Одно из самых значительных изменений в веб-платформе, которое принес WebAssembly, — это появление альтернативных моделей построения пользовательских интерфейсов. Вместо того чтобы использовать DOM и CSS, где каждая кнопка и текстовое поле представлены отдельными элементами в дереве документа, WASM-фреймворки могут рендерить интерфейс в `<canvas>` элемент, минуя DOM целиком. Это переопределяет, как мы думаем о веб-приложениях: вопрос больше не стоит как "JavaScript против WASM", а как "DOM против рисования на холсте".

## Canvas + WASM вместо React/Vue для сложных графиков

Принципиальное различие между традиционными JS-фреймворками и WASM-подходом к UI — это способ рендеринга. React и Vue строят дерево реальных DOM-элементов, с которыми браузер работает нативно. WASM-фреймворки, наоборот, компилируют Dart или Rust в WASM и рисуют каждый пиксель интерфейса на одном HTML-элементе `<canvas>`.

### Архитектура Canvas-рендеринга

Когда приложение рендерится в canvas, браузер больше не видит отдельные UI-компоненты. Вместо дерева DOM существует один элемент, внутри которого движок отрисовывает всё самостоятельно — кнопки, текст, изображения, анимации. Это даёт несколько ключевых преимуществ:

**Производительность при сложной анимации и интенсивных обновлениях.** Поскольку DOM обновлений нет, отсутствуют пересчёты стилей (reflow) и перерисовки (repaint), которые являются узким местом для сложных анимаций. Canvas-рендеринг позволяет достигать стабильных 60 FPS даже при десятках тысяч одновременно двигающихся объектов.

**Консистентность на всех платформах.** Один и тот же код рисует интерфейс одинаково на всех браузерах и устройствах. Нет необходимости учитывать различия в реализации CSS или поведении DOM.

### Flutter Web: экосистемный лидер

Flutter Web — самый яркий пример этого подхода. В 2026 году Flutter переходит на WASM-рендеринг по умолчанию для веб-приложений. Flutter компилирует Dart-код в WebAssembly (через режим `--wasm`) и использует движок `skwasm` — компактную версию Skia (графический движок Flutter), скомпилированную в WASM.

Производительность Flutter Web в WASM-режиме значительно улучшилась:
- **skwasm** добавляет около 1.1 МБ к загрузке (на 400 КБ меньше, чем прежний CanvasKit на 1.5 МБ).
- Рендеринг может выполняться в отдельном Web Worker, используя несколько ядер процессора через SharedArrayBuffer.
- Время запуска и кадровая производительность заметно лучше по сравнению со старой CanvasKit-реализацией.

Однако у такого подхода есть цена: для старта приложения необходимо загрузить и инициализировать рантайм Skia. Это делает Flutter Web неприменимым для публичных, SEO-зависимых сайтов, но идеальным для авторизованных дашбордов и внутренних инструментов.

### Инструмент с минимальным рантаймом: Slint

**Slint** — UI-фреймворк на Rust, который рендерится в canvas через WebGL. Он не использует ни DOM, ни CSS, что даёт консистентный вид на всех платформах. Slint компилируется в WASM и требует только элемент `<canvas id="canvas">` в HTML.

Поскольку в Slint нет DOM, он не поддерживает веб-специфичные функции — экранные ридеры недоступны, текст рендерится напрямую, а не через браузерные механизмы. Поэтому Slint рекомендуется не для общих веб-приложений, а для демонстраций, инструментов и приложений, где консистентность рендеринга важнее веб-интеграции.

В 2026 году Slint также развивает поддержку WebGPU и C++ API для WASM, что может сделать его серьёзным конкурентом Flutter в сфере высокопроизводительных UI.

### EUV и Rue: декларативные UI на Rust

Для разработчиков Rust, которые хотят приблизиться к знакомой модели React или Vue, в 2026 году доступны два проекта:

**EUV** — декларативный кросс-платформенный UI-фреймворк на Rust с виртуальным DOM, реактивными сигналами и HTML-макросами для WebAssembly. Он позволяет писать компоненты в стиле JSX прямо в Rust и рендерить их в WASM.

**Rue** — реактивный UI-фреймворк, вдохновлённый Vue 3 и его Composition API. Rue предлагает знакомые концепции: сигналы (как `ref()` в Vue), вычисляемые значения, эффекты с авто-отслеживанием зависимостей, виртуальный DOM с алгоритмом диффинга (LIS — тот же, что в Vue 3) и HTML-макросы для декларативных шаблонов.

Оба фреймворка компилируются в WASM через `wasm-bindgen` и позволяют писать UI на Rust с сохранением знакомой реактивной модели.

### Coi: компонентный язык с O(1)-реактивностью

Coi — это компонентно-ориентированный язык, спроектированный для высокопроизводительных веб-приложений с WASM. В отличие от традиционных фреймворков, Coi не использует виртуальный DOM для диффинга. Вместо этого он статически анализирует изменения на этапе компиляции и связывает изменения состояния напрямую с конкретными элементами в буфере команд.

Coi транслируется в C++, затем компилируется в WASM через собственный тулчейн WebCC. В бенчмарках Coi обходит React и Vue на таблице с 1000 строк — как по созданию строк, так и по обновлениям и перестановкам — за счёт того, что исключает шаг "диффинга" и минимизирует переходы через границу WASM↔JS.

## Рендеринг нативных UI-библиотек (Flutter, Slint)

WebAssembly позволяет переносить в браузер UI-библиотеки, которые изначально разрабатывались для нативных платформ. Это даёт разработчикам возможность использовать одни и те же компоненты на мобильных устройствах, десктопе и в вебе.

### Flutter Web: от мобильного кода к веб-рендерингу

Flutter был создан как кроссплатформенный UI-тулкит для мобильных приложений. В 2026 году фреймворк завершает ключевые миграции: переход на рендерер Impeller на Android и на WASM для веба.

При компиляции в WASM (`flutter build web --wasm`) Dart-код компилируется в WASM, а Flutter Engine на основе Skia рендерит всё в canvas. Это позволяет одному коду работать и на iOS (через Impeller), и на Android, и на вебе, с идентичным визуальным результатом.

### Slint: один код для десктопа, мобильных и веба

Slint позволяет писать UI на специальном языке Slint или напрямую на Rust, а затем компилировать его для разных платформ. В 2026 году Slint поддерживает WASM-рендеринг через canvas, хотя текст и доступность пока уступают нативным веб-решениям.

Пример проекта **Osmosis** использует Slint для создания приложения, которое работает на Linux, Android и в вебе (через WASM) из единой кодовой базы. Архитектура разделена на доменный слой (`app-core`), сетевой слой (`api`) и UI-слой (`ui` на Slint), причём `app-core` не зависит от Slint или сетевого кода, что позволяет тестировать бизнес-логику изолированно.

## Декларативный UI на WASM

Главный вызов при разработке UI на WASM — это необходимость эффективно управлять реактивностью и обновлениями. Традиционный подход JavaScript-фреймворков с виртуальным DOM и диффингом переносится в мир WASM, но появляются и более эффективные альтернативы.

### Виртуальный DOM на WASM

Фреймворки вроде EUV и Rue реализуют виртуальный DOM на Rust и выполняют диффинг внутри WASM. Это позволяет использовать знакомую декларативную модель (компоненты с состоянием, перерендеринг при изменении) без потери производительности. Rust-реализация VDOM может работать быстрее JavaScript-аналога за счёт статической типизации и отсутствия сборщика мусора в критических путях.

### Реактивность без VDOM

Coi использует другой подход: вместо VDOM и диффинга он анализирует код на этапе компиляции и связывает состояния напрямую с элементами DOM (или canvas). Когда состояние меняется, обновляется только связанный элемент — без шага сравнения деревьев. Это даёт O(1)-обновления и минимальный размер бандла.

### Бенчмарки: Coi против React и Vue

В бенчмарке на таблице с 1000 строк Coi показывает лучшие результаты по трём метрикам: создание строк, обновление строк и перестановка строк. Причина — отсутствие шага диффинга и минимизация переходов между WASM и JavaScript через буфер команд.

Сравнение рендеринга 10,000 прямоугольников на canvas показывает разницу ещё заметнее:
- **Emscripten** (стандартная связка C++ → WASM) достигает ~40 FPS.
- **Подход с минимальным рантаймом и буфером команд** — ~100 FPS.

---

WebAssembly как UI Execution Layer — это не просто экспериментальная технология. Это зрелая платформа, на которой строятся production-приложения. Flutter Web делает WASM рендеринг стандартом, Slint позволяет использовать один UI-код на всех платформах, а фреймворки вроде EUV, Rue и Coi предоставляют знакомый декларативный опыт для Rust-разработчиков. Ключевое преимущество перед традиционным подходом — контролируемый рендеринг, который даёт стабильную производительность на сложных интерфейсах и консистентность на всех платформах. Цена — отсутствие SEO и доступности из коробки, что делает этот подход идеальным для авторизованных приложений, но не для публичных сайтов.
