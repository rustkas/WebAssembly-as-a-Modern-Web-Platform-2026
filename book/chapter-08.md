# Глава 8. Структура WASM Module

WebAssembly-модуль — это самодостаточная единица кода, которая может быть скомпилирована, передана по сети, загружена и выполнена в совместимой среде . Каждый модуль представляет собой бинарный файл с расширением `.wasm`, содержащий исполняемый код и метаданные, необходимые для его корректной загрузки.

В этой главе мы разберём внутреннее устройство WASM-модуля: как он организован в секции, как читать и парсить бинарный формат, какие инструменты существуют для анализа и какие возможности предоставляют кастомные секции.

## Секции модуля

Бинарное кодирование модуля организовано в секции. Каждая секция содержит один компонент модуля, за исключением определений функций, которые разделены на две секции: объявление типов в секции функций и тела функций в секции кода . Это разделение позволяет выполнять параллельную и потоковую компиляцию функций модуля .

Каждый WASM-файл начинается с 8-байтового заголовка :

```
00 61 73 6D   ;; магическое число: "\0asm"
01 00 00 00   ;; версия: 1
```

Магическое число `0x00 0x61 0x73 0x6D` идентифицирует файл как WebAssembly. Версия `0x01 0x00 0x00 0x00` соответствует актуальной спецификации .

После заголовка файл состоит из последовательности секций. Каждая секция имеет :

- Однобайтовый идентификатор секции;
- 32-битную длину содержимого в байтах;
- Собственно содержимое, структура которого зависит от идентификатора секции.

Каждая секция опциональна — пропущенная секция эквивалентна присутствующей с пустым содержимым .

В спецификации определены следующие идентификаторы секций :

| ID | Секция | Назначение |
|----|--------|------------|
| 0 | Custom | Пользовательские метаданные, отладочная информация |
| 1 | Type | Сигнатуры функций (типы) |
| 2 | Import | Импорты из окружения |
| 3 | Function | Объявления функций (индексы типов) |
| 4 | Table | Таблицы ссылок на функции |
| 5 | Memory | Определения линейной памяти |
| 6 | Global | Глобальные переменные модуля |
| 7 | Export | Экспорты для окружения |
| 8 | Start | Опциональная функция входа |
| 9 | Element | Инициализация таблиц |
| 10 | Code | Тела функций (инструкции) |
| 11 | Data | Инициализация линейной памяти |
| 12 | Data Count | Количество сегментов данных |
| 13 | Tag | Определения тегов для обработки исключений |

### Секция Type (ID 1)

Секция типов декодируется в вектор определений рекурсивных типов модуля . В минимальной версии WebAssembly секция типов содержит сигнатуры функций. Каждая сигнатура начинается с байта `0x60`, за которым следуют типы параметров и возвращаемых значений .

Например, сигнатура функции, принимающей два 32-битных целых числа и возвращающей 32-битное целое:
```
60 02 7F 7F 01 7F
```
где `02` — количество параметров, `7F` — тип `i32`, `01` — количество возвращаемых значений.

### Секция Import (ID 2)

Секция импортов декодируется в список импортов модуля . Каждый импорт определяет модуль, имя поля и описание импорта :

```
02           ;; ID секции: Import
11           ;; Длина секции: 17 байт
01           ;; Количество импортов: 1
03 65 6E 76  ;; Имя модуля: "env"
08 70 72 69 6E 74 5F 73 74 72  ;; Имя поля: "print_str"
00           ;; Вид импорта: Function
00           ;; Индекс типа: 0
```

Имена модуля и поля кодируются как строки UTF-8 с префиксом длины . Вид импорта может быть `00` (функция), `01` (таблица), `02` (память) или `03` (глобальная переменная) .

### Секция Function (ID 3)

Секция функций декодируется в список индексов типов, классифицирующих функции, определённые в модуле . Тела функций кодируются отдельно в секции кода. Это разделение позволяет рантайму начать компиляцию функций до того, как загружены все тела .

```
03           ;; ID секции: Function
05           ;; Длина секции: 5 байт
04           ;; Количество функций: 4
00 01 10 02  ;; Индексы типов для каждой функции
```

Каждый байт после количества функций — это ULEB128-кодированный индекс, указывающий в секцию типов .

### Секция Memory (ID 5)

Секция памяти декодируется в список определений памяти модуля . Каждое определение памяти включает минимальное и опциональное максимальное количество страниц памяти (одна страница = 64 КБ) :

```
05           ;; ID секции: Memory
03           ;; Длина секции: 3 байта
01           ;; Количество блоков памяти: 1
00 11        ;; Флаги=0 (только минимум), минимум=17 страниц
```

Флаги `00` означают, что указан только минимум. Максимум не задан, и память может расти неограниченно .

### Секция Export (ID 7)

Секция экспортов декодируется в список экспортов модуля . Каждый экспорт определяет имя и ссылку на экспортируемую сущность :

```
07           ;; ID секции: Export
0C           ;; Длина секции: 12 байт
01           ;; Количество экспортов: 1
04 6D 61 69 6E  ;; Имя: "main"
00              ;; Вид экспорта: Function
03              ;; Индекс функции: 3
```

Виды экспорта: `00` (функция), `01` (таблица), `02` (память), `03` (глобальная переменная) .

### Секция Code (ID 10)

Секция кода декодируется в список записей кода — пар списков локальных переменных и выражений. Они представляют тела функций, определённых в модуле .

Каждая запись кода состоит из :
- 32-битной длины тела функции в байтах;
- Объявления локальных переменных (сжатых в список пар `count + тип`);
- Тела функции как выражения.

Например, функция, объявляющая две локальные переменные типа `i32`:
```
01           ;; Количество записей в секции кода
09           ;; Длина тела функции: 9 байт
01           ;; Одна группа локальных переменных
01 7F        ;; 1 переменная типа i32
23 00 0B     ;; Инструкции: global.get 0; end
```

Объявления локальных переменных сжимаются — несколько переменных одного типа группируются. Если функция объявляет 3 локальные переменные типа `i32`, это кодируется как `03 7F` .

### Секция Data (ID 11)

Секция данных декодируется в список сегментов данных, инициализирующих линейную память . Каждый сегмент определяет индекс памяти, смещение и последовательность байтов для записи:

```
0B           ;; ID секции: Data
15           ;; Длина секции: 21 байт
01           ;; Количество сегментов: 1
00           ;; Флаг: активный сегмент
41 00 0B     ;; Выражение смещения: i32.const 0; end
04 68 65 6C 6C  ;; Данные: "hell"
```

Флаг `00` указывает на активный сегмент (данные записываются в память при инстанцировании) .

### Custom Section (ID 0)

Кастомные секции имеют идентификатор 0. Они предназначены для отладочной информации или сторонних расширений и игнорируются семантикой WebAssembly .

Содержимое кастомной секции состоит из имени, идентифицирующего секцию, и непроинтерпретированной последовательности байтов для пользовательского использования :

```
00           ;; ID секции: Custom
0F           ;; Длина секции: 15 байт
04 6E 61 6D 65  ;; Имя: "name"
...          ;; Пользовательские данные
```

Важное свойство кастомных секций: если реализация интерпретирует данные кастомной секции, ошибки в этих данных или размещении секции не должны делать модуль невалидным . Это гарантирует, что инструменты (например, отладчики) могут добавлять свои данные в модуль, не нарушая его корректность.

#### Секция Name

Спецификация определяет одну специальную кастомную секцию — **секцию имён**. Она появляется не более одного раза в модуле и только после секции данных . Её назначение — прикреплять читаемые имена к определениям в модуле для использования отладчиками или при рендеринге модуля в текстовой форме .

Секция имён состоит из последовательности подсекций :

| ID | Подсекция | Назначение |
|----|-----------|------------|
| 0 | Module name | Имя модуля |
| 1 | Function names | Имена функций (индекс → имя) |
| 2 | Local names | Имена локальных переменных (функция → индекс → имя) |
| 4 | Type names | Имена типов (индекс → имя) |
| 10 | Field names | Имена полей структур (тип → индекс → имя) |
| 11 | Tag names | Имена тегов (индекс → имя) |

Имена представляются в Unicode, закодированном в UTF-8, и не обязаны быть уникальными .

## Бинарный формат и инструменты

### Инструменты WABT

WABT (WebAssembly Binary Toolkit) — это набор инструментов для работы с WebAssembly, включающий :

- **wat2wasm** — трансляция из текстового формата в бинарный.
- **wasm2wat** — обратная трансляция из бинарного в текстовый формат.
- **wasm-objdump** — вывод информации о WASM-бинарнике (аналог objdump).
- **wasm-interp** — интерпретатор для выполнения WASM-файлов.
- **wasm-decompile** — декомпиляция WASM в C-подобный синтаксис.
- **wasm-strip** — удаление секций из WASM-файла.
- **wasm-validate** — валидация WASM-файла.
- **wasm2c** — конвертация WASM в C-исходники.

Эти инструменты нацелены на полную точность и соответствие спецификации (например, 1:1-преобразования без изменений инструкций), в отличие от Binaryen, который фокусируется на оптимизации .

### wasm-objdump

`wasm-objdump` — основной инструмент для инспектирования WASM-модулей. Ключевые опции :

- `-h, --headers` — вывод заголовков всех секций.
- `-j, --section=SECTION` — выбор только одной секции.
- `-s, --full-contents` — вывод сырого содержимого секций.
- `-d, --disassemble` — дизассемблирование тел функций.
- `-x, --details` — вывод детальной информации о секциях.

Пример использования:
```
wasm-objdump -x test.wasm
```

### wasm-interp

Интерпретатор для выполнения WASM-модулей :
```
# Запуск всех экспортированных функций
wasm-interp test.wasm --run-all-exports

# Запуск с трассировкой выполнения
wasm-interp test.wasm --run-all-exports --trace

# Запуск spec-тестов
wasm-interp test.json --spec
```

## Методы чтения и парсинга

### Формат LEB128

Все целочисленные значения в WASM-бинарнике кодируются в формате LEB128 (Little Endian Base 128) . Это формат переменной длины, где каждый байт содержит 7 бит данных и бит продолжения (старший бит указывает, есть ли ещё байты).

Для декодирования используется функция, читающая байты до тех пор, пока не встретит байт без установленного старшего бита .

### Низкоуровневое чтение

При парсинге WASM-файла необходимо :

1. Прочитать 8-байтовый заголовок (магическое число и версия).
2. Последовательно читать секции. Для каждой секции:
   - Прочитать ID (один байт).
   - Прочитать длину (ULEB128).
   - Обработать содержимое в соответствии с ID.
3. Пропустить неизвестные кастомные секции, используя длину.

Декодер должен проверять, что длина секции соответствует фактической длине содержимого . Несоответствие делает модуль мальформированным.

### Инструменты для разных языков

Существуют реализации декодеров для разных языков. Например, для Python доступен модуль `wasm-tob`, позволяющий декодировать и дизассемблировать WASM-модули :

```python
from wasm_tob import decode_module

with open('module.wasm', 'rb') as raw:
    mod_iter = iter(decode_module(raw.read()))
    header, header_data = next(mod_iter)
    for cur_sec, cur_sec_data in mod_iter:
        print(cur_sec_data.id)
```

## Кастомизация и метаданные

Кастомные секции дают разработчикам инструментов мощный механизм для расширения WASM-модулей без нарушения их семантики.

### Name Section для отладки

Секция имён — ключевой инструмент для отладки. Без неё отладчик видит только числовые индексы функций и локальных переменных. С секцией имён стек вызовов становится читаемым:

```
# Без секции имён
wasm_function[42] at 0x1234

# С секцией имён
process_data at 0x1234
```

### Пользовательские кастомные секции

Разработчики могут создавать собственные кастомные секции для различных целей:
- **Source maps** — привязка WASM-инструкций к исходному коду на C++/Rust.
- **Информация о сборке** — версия компилятора, флаги оптимизации, время сборки.
- **Метрики производительности** — предварительно вычисленные профили.
- **Проверки целостности** — подписи или хеши для верификации модуля.

При создании кастомной секции важно помнить: если реализация интерпретирует данные секции, ошибки в этих данных не должны делать модуль невалидным . Это значит, что инструменты должны корректно обрабатывать некорректные данные в кастомных секциях, просто игнорируя их.

### Extended Const и другие расширения

WABT поддерживает множество экспериментальных и стандартизированных расширений WASM через флаги :

 | Расширение | Флаг | Статус по умолчанию |
 |------------|------|---------------------|
 | Exception Handling | `--enable-exceptions` | Отключено (экспериментальный статус) |
 | Threads | `--enable-threads` | Отключено |
 | SIMD | `--disable-simd` | Включено |
 | Memory64 | `--enable-memory64` | Отключено |
 | Multi-Memory | `--enable-multi-memory` | Отключено |
 | Function References | `--enable-function-references` | Отключено |
 | Garbage Collection | `--enable-gc` | Отключено |

Эти флаги управляют тем, какие возможности спецификации распознаются при парсинге и компиляции WASM-модулей.
