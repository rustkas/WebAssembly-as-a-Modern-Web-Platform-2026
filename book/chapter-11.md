# Глава 11. Imports и Exports

WebAssembly-модули не существуют изолированно. Для того чтобы модуль мог взаимодействовать с окружением — будь то браузер, JavaScript-рантайм или другая WASM-среда, — он должен предоставлять и получать функциональность через чётко определённые интерфейсы. Эти интерфейсы реализуются через два механизма: **импорты** (imports) и **экспорты** (exports) .

Импорты позволяют модулю объявлять зависимости от функций, памяти, таблиц и глобальных переменных, предоставляемых окружением. Экспорты делают внутренние сущности модуля доступными для окружения .

## Передача функций из окружения в модуль

WebAssembly-модуль объявляет импорты в специальной секции модуля . Каждый импорт идентифицируется двухуровневым пространством имён: имя модуля и имя элемента внутри этого модуля .

```
(module
  (func $console_log (import "js" "console.log") (param i32))
)
```

В этом примере модуль импортирует функцию `console.log` из модуля `js`. Сигнатура функции указывает, что она принимает один параметр типа `i32` .

При инстанцировании модуля окружение должно предоставить объект, содержащий все требуемые импорты . В браузере это выглядит так:

```javascript
const importObject = {
  js: {
    "console.log": (arg) => console.log(arg)
  }
};

WebAssembly.instantiate(bytes, importObject).then(result => {
  // Модуль теперь может вызвать импортированную функцию
});
```

В WebAssembly можно импортировать не только функции, но и другие типы сущностей: таблицы, памяти, глобальные переменные и теги для обработки исключений .

Каждый импорт создаёт индекс в соответствующем пространстве имён. Индексы импортов предшествуют индексам определений, созданных внутри самого модуля . Например, если модуль импортирует две функции, они получают индексы 0 и 1, а первая функция, определённая в модуле, получает индекс 2.

Особенность импортов в WebAssembly: имена импортов не обязаны быть уникальными. Можно импортировать одно и то же имя несколько раз, даже с разными типами. Однако спецификация не требует, чтобы окружение поддерживало такие перегрузки .

## Экспорт функций из модуля

Экспорты делают внутренние сущности модуля доступными для окружения . Каждый экспорт имеет уникальное имя и ссылку на сущность внутри модуля .

```
(module
  (func $add (param i32 i32) (result i32)
    local.get 0
    local.get 1
    i32.add
  )
  (export "add" (func $add))
)
```

После инстанцирования модуля экспортированная функция становится доступна через свойство `exports` инстанса :

```javascript
const result = instance.exports.add(2, 3); // 5
```

Экспортировать можно все те же типы сущностей, которые можно импортировать: функции, таблицы, памяти, глобальные переменные и теги .

Важное свойство экспортов: имена должны быть уникальными в пределах модуля .

При экспорте функции важно понимать, что возвращается именно ссылка на функцию, которая при вызове может принимать аргументы и возвращать значения в соответствии со своей сигнатурой. В примере ниже используется Wasmer (Rust-рантайм) для демонстрации работы с экспортированными функциями :

```rust
// В модуле экспортирована функция get_one
let get_one: TypedFunction<(), f32> = 
    instance.exports.get_function("get_one")?.typed(&store)?;
let one_value = get_one.call(&mut store)?; // 1.0
```

## Экспорт памяти и глобальных переменных

### Память

Линейная память — один из ключевых экспортируемых элементов WebAssembly . Модуль может экспортировать свою память, позволяя окружению читать и записывать данные напрямую в буфер модуля .

Модуль с экспортом памяти:

```
(module
  (memory (export "mem") 1)
  (func (export "accumulate") (param $ptr i32) (param $length i32) ...)
)
```

Из JavaScript доступ к экспортированной памяти осуществляется через свойство `exports` инстанса :

```javascript
const memory = instance.exports.mem;
const i32 = new Uint32Array(memory.buffer);

// Запись данных в память модуля
for (let i = 0; i < 10; i++) {
  i32[i] = i;
}

// Вызов функции, работающей с этими данными
const sum = instance.exports.accumulate(0, 10);
```

Память экспортируется как объект `WebAssembly.Memory`. Её буфер (`ArrayBuffer`) может использоваться для создания типизированных массивов, что позволяет эффективно обмениваться данными между JavaScript и WASM .

Экспорт памяти особенно полезен, когда нужно передать большие объёмы данных (изображения, аудио, симуляции) без сериализации через структурированное клонирование. Вместо копирования данные записываются непосредственно в буфер памяти модуля, а затем WASM-код обрабатывает их.

### Глобальные переменные

Глобальные переменные в WebAssembly могут быть как неизменяемыми (`const`), так и изменяемыми (`mut`) .

```
(module
  (global $one (export "one") f32 (f32.const 1))
  (global $some (export "some") (mut f32) (f32.const 0))
)
```

Экспортированные глобальные переменные доступны из окружения для чтения и (если они изменяемые) для записи :

```javascript
// Чтение значения глобальной переменной
const oneValue = instance.exports.one.value;
const someValue = instance.exports.some.value;

// Запись значения в изменяемую глобальную переменную
instance.exports.some.value = 42.0;
```

В Rust-рантайме Wasmer работа с экспортированными глобальными переменными выглядит так :

```rust
let one = instance.exports.get_global("one")?;
let some = instance.exports.get_global("some")?;

// Проверка типа и изменяемости
let one_type = one.ty(&store); // Mutability::Const, Type::F32
let some_type = some.ty(&store); // Mutability::Var, Type::F32

// Чтение значений
let one_value = one.get(&store); // 1.0
let some_value = some.get(&store); // 0.0

// Попытка записи в неизменяемую глобальную переменную вызовет ошибку
assert!(one.set(&mut store, Value::F32(42.0)).is_err());

// Запись в изменяемую глобальную переменную
some.set(&mut store, Value::F32(42.0))?;
```

Глобальные переменные полезны для обмена простыми конфигурационными значениями, состояниями и флагами между WASM-модулем и окружением. В отличие от памяти, они не требуют работы с буферами и типизированными массивами.

## Таблицы функций (Table)

Таблицы — это специальный механизм WebAssembly для косвенных вызовов функций . В отличие от прямой ссылки на функцию, таблица хранит массив ссылок на функции. Это позволяет выбирать функцию для вызова динамически, на основе индекса .

### Определение таблицы

Таблица определяется с указанием начального размера и типа хранимых ссылок :

```
(module
  (type $ret_i32 (func (result i32)))
  
  (func $f1 (result i32) (i32.const 1))
  (func $f2 (result i32) (i32.const 2))
  
  (table $return_values (export "table") 2 funcref)
  
  (elem (table 0) $f1 $f2)
)
```

Тип таблицы может быть `funcref` (ссылки на функции внутри WebAssembly) или `externref` (ссылки на внешние значения, такие как JavaScript-объекты) .

### Косвенный вызов

Для вызова функции через таблицу используется инструкция `call_indirect` :

```
(func (export "accessTable") (param $index i32) (result i32)
  (call_indirect (type $ret_i32) (local.get $index))
)
```

При выполнении `call_indirect` рантайм проверяет, что функция по указанному индексу имеет ожидаемую сигнатуру. Несовпадение сигнатуры вызывает ловушку (trap) .

### Модификация таблиц во время выполнения

Таблицы могут быть изменены во время выполнения с помощью инструкций `table.set`, `table.fill` и `table.grow` . Это позволяет динамически добавлять и заменять функции, что критически важно для реализации виртуальных таблиц, динамической загрузки плагинов и других паттернов.

В будущих версиях WebAssembly планируется поддержка множественных таблиц в одном модуле, но в текущей спецификации модуль может иметь не более одной таблицы .

### Экспорт таблицы

Как и другие сущности, таблица может быть экспортирована, что позволяет окружению читать и модифицировать её :

```
(export "table" (table $return_values))
```

Из JavaScript экспортированная таблица представлена объектом `WebAssembly.Table`:

```javascript
const table = instance.exports.table;
console.log(table.length); // 2
console.log(table.get(0)); // ссылка на первую функцию
table.set(0, newFunction); // замена функции в таблице
```

Таблицы функций — это мощный инструмент, который позволяет реализовывать паттерны, требующие косвенных вызовов: виртуальные методы, колбэки, полиморфизм, диспетчеризацию сообщений. В сочетании с возможностью модификации таблиц во время выполнения они открывают возможности для динамических архитектур внутри WebAssembly.

---

Импорты и экспорты составляют основу коммуникации WebAssembly с окружением. Импорты позволяют модулю использовать внешние ресурсы, экспорты делают внутренние сущности доступными снаружи. Функции, память, глобальные переменные и таблицы могут быть как импортированы, так и экспортированы. Это создаёт гибкую систему интероперабельности, которая лежит в основе интеграции WASM с JavaScript, а также взаимодействия между несколькими WASM-модулями.
