# Приложение C. Глоссарий терминов

Этот глоссарий содержит определения ключевых терминов, используемых в книге «WebAssembly as a Modern Web Platform 2026».

---

## A

**ABI (Application Binary Interface)** — интерфейс на уровне бинарного кода, определяющий, как функции вызываются, как передаются аргументы и как организована память.

**AOT (Ahead-Of-Time) Compilation** — компиляция WASM-байткода в машинный код до выполнения, в отличие от JIT-компиляции, которая происходит во время выполнения.

**AssemblyScript** — язык, компилирующий вариант TypeScript в WebAssembly.

**Asynchronous Component Model** — Component Model с нативной поддержкой асинхронных вызовов (WASI 0.3).

**Atomics** — набор операций для атомарного доступа к разделяемой памяти (SharedArrayBuffer), предотвращающих состояния гонки в многопоточных приложениях.

---

## B

**Binaryen** — набор инструментов и библиотек для оптимизации и трансформации WebAssembly-модулей. Включает `wasm-opt` — утилиту для агрессивной оптимизации размера и производительности.

**Brotli** — алгоритм сжатия, обеспечивающий наилучшее сжатие для WASM-файлов.

---

## C

**Cache API** — браузерный API для программного управления кэшированием HTTP-ответов, включая WASM-модули.

**Capability-based Security** — модель безопасности, в которой доступ к ресурсам предоставляется через явно переданные возможности (capabilities). В WASI модуль не имеет доступа по умолчанию — всё должно быть явно разрешено.

**COEP (Cross-Origin-Embedder-Policy)** — HTTP-заголовок, требующий, чтобы кросс-оригинальные ресурсы загружались с явным разрешением. Необходим для использования SharedArrayBuffer.

**Component Model** — спецификация, определяющая, как WASM-бинарные файлы упаковываются, линкуются и взаимодействуют друг с другом через языконезависимые интерфейсы.

**COOP (Cross-Origin-Opener-Policy)** — HTTP-заголовок, изолирующий контекст документа от других окон. Необходим для использования SharedArrayBuffer.

**Cranelift** — оптимизирующий компилятор, используемый в Wasmtime для генерации машинного кода из WASM-байткода.

**Cross-origin Isolated** — состояние страницы, при котором она защищена от Spectre-подобных атак и может использовать SharedArrayBuffer.

---

## D

**DWARF** — формат отладочной информации, используемый для символизации стек-трейсов WASM-модулей, привязывая адреса к исходным файлам и номерам строк.

---

## E

**Emscripten** — тулчейн для компиляции C/C++ в WebAssembly, включающий эмуляцию POSIX-системы и поддержку OpenGL/SDL.

**Exception Handling** — механизм обработки исключений в WebAssembly, основанный на тегах (tags) и инструкции `try_table`, реализованный в спецификации Exception Handling Proposal (принята в 2023 году).

**exnref** — ссылочный тип для объектов исключений, используемый для перехвата и повторного бросания исключений в WebAssembly.

**Export** — объявление, делающее внутреннюю сущность модуля (функцию, память, таблицу, глобальную переменную) доступной для окружения.

---

## F

**Fragmentation** — фрагментация линейной памяти, когда свободное пространство разделено на множество мелких участков, непригодных для выделения больших объектов.

**funcref** — ссылочный тип, указывающий на функцию WebAssembly. Используется в таблицах для косвенных вызовов.

---

## G

**Garbage Collection (GC)** — механизм автоматического управления памятью, включённый в WebAssembly 3.0. Позволяет языкам с управляемой памятью компилироваться в WASM без встраивания собственного GC.

**GPGPU (General-Purpose GPU Computing)** — использование GPU для вычислений общего назначения, а не только для графики. В WebGPU реализовано через compute shaders.

---

## I

**Import** — объявление зависимости модуля от внешней сущности (функции, памяти, таблицы, глобальной переменной).

**Instantiate** — процесс создания исполняемого экземпляра WASM-модуля, связывающий код с конкретным окружением (памятью, импортами).

**Interface** — в WIT — набор функций и типов, определяющий контракт между компонентами.

---

## J

**JIT (Just-In-Time) Compilation** — компиляция WASM-байткода в машинный код во время выполнения. Используется в браузерах и некоторых серверных рантаймах.

**js-sys** — Rust-библиотека, предоставляющая привязки к встроенным объектам ECMAScript (Array, Object, String, Promise и др.).

---

## L

**LEB128** — формат кодирования целых чисел переменной длины, используемый в WASM-бинарном формате.

**Linear Memory** — непрерывный массив байтов, доступный WASM-модулю для чтения и записи. Измеряется в страницах по 64 КБ.

**LTO (Link-Time Optimization)** — оптимизация на этапе линковки, позволяющая компилятору видеть весь код программы и удалять мёртвый код, что уменьшает размер бинарного файла.

---

## M

**Memory64** — расширение WebAssembly для 64-битной адресации памяти, позволяющее адресовать до 16 эксабайт (вместо 4 ГБ в 32-битной).

**MIME Type** — `application/wasm` — правильный MIME-тип для WASM-файлов. Необходим для потоковой компиляции через `instantiateStreaming`.

**Module** — скомпилированный WASM-бинарный файл, содержащий код, данные и метаданные. Может быть инстанцирован многократно.

---

## P

**Package** — в WIT — единица организации интерфейсов, идентифицируемая именем и версией.

**Panic** — в Rust — необработанная ошибка. В WebAssembly по умолчанию приводит к ловушке (trap), если не настроен `panic=unwind`.

**POSIX (Portable Operating System Interface)** — стандарт интерфейсов для Unix-подобных операционных систем.

**Preopen** — в WASI — директория или файл, предварительно открытый до инстанцирования модуля, что ограничивает доступ модуля только к этим ресурсам.

---

## R

**Reference Types** — группа типов для работы с непрозрачными ссылками на значения, управляемые хостом (`externref`) или функциями (`funcref`).

**Relaxed SIMD** — расширение SIMD, позволяющее рантаймам выбирать наиболее эффективные аппаратные инструкции, даже если результат может незначительно отличаться.

**Resource** — в WIT — непрозрачный тип с методами, позволяющий компонентам обмениваться ссылками на данные без раскрытия их внутреннего устройства.

---

## S

**Section** — структурная единица WASM-модуля (Type, Function, Code, Data, Custom и др.), каждая со своим идентификатором.

**SemVer (Semantic Versioning)** — схема версионирования (`MAJOR.MINOR.PATCH`), используемая для управления совместимостью WASM-интерфейсов.

**SharedArrayBuffer** — буфер, разделяемый между несколькими Web Workers и WASM-модулями, позволяющий разделять память без копирования. Требует кросс-оригинальной изоляции.

**SIMD (Single Instruction, Multiple Data)** — технология, позволяющая одной инструкции обрабатывать несколько элементов данных одновременно. В WASM представлена типом `v128` и более чем 200 инструкциями.

**Source Maps** — формат, связывающий скомпилированный WASM-код с исходным кодом (например, C++ или Rust) для отладки.

**Startup Cost** — время от начала загрузки WASM-модуля до момента его готовности к выполнению. Включает загрузку, компиляцию и инстанцирование.

**Streaming Compilation** — компиляция WASM-кода по мере поступления данных из сети, без ожидания полной загрузки файла. Реализована в `instantiateStreaming` и `compileStreaming`.

---

## T

**Table** — изменяемый массив ссылок на функции (`funcref`), используемый для косвенных вызовов через `call_indirect`.

**Tag** — в Exception Handling — идентификатор типа исключения, определяющий его сигнатуру (параметры).

**Tiered Compilation** — стратегия компиляции в два этапа: быстрая базовая компиляция (Liftoff) для быстрого старта и фоновая оптимизация (TurboFan) для пиковой производительности.

**TinyGo** — альтернативный компилятор Go для WebAssembly, производящий значительно меньшие бинарные файлы (100-500 КБ вместо 5-10 МБ).

**Trap** — немедленное прерывание выполнения WASM-модуля при попытке выйти за границы памяти, вызвать несуществующую функцию или выполнить недопустимую операцию.

**Try_table** — инструкция WebAssembly для обработки исключений, комбинирующая try, catch и catch_all в одной конструкции.

---

## W

**WASI (WebAssembly System Interface)** — стандартизированный интерфейс для доступа WASM-модулей к системным ресурсам (файловая система, сеть, время). Основан на модели capability-based security.

**WASI Preview** — этап развития WASI: Preview 1 (базовый), Preview 2 (Component Model), Preview 3 (нативная асинхронность).

**wasm-bindgen** — Rust-инструмент для генерации привязок между Rust-кодом и JavaScript, обеспечивающий бесшовный интероп.

**wasm-opt** — утилита из набора Binaryen для оптимизации и сжатия WASM-модулей. Флаг `-Oz` даёт максимальное сжатие.

**Wasmtime** — основной WASM-рантайм от Bytecode Alliance, написанный на Rust. Эталонная реализация WASI и Component Model.

**Webble** — асинхронный многопоточный рантайм для веба, запускающий Rust-футуры в пуле Web Workers с разделяемой памятью.

**WebGPU** — современный API для высокопроизводительной графики и вычислений на GPU в браузере. Пришёл на смену WebGL.

**web-sys** — Rust-библиотека, предоставляющая привязки ко всем Web API (DOM, Canvas, WebGPU, WebSocket и др.).

**WIT (WebAssembly Interface Type)** — язык описания интерфейсов для Component Model. Определяет, какие функции компонент экспортирует/импортирует и какие типы передаёт.

**World** — в WIT — коллекция импортов и экспортов, определяющая полный контракт компонента.

---

## Z

**Zero-copy** — техника передачи данных между WASM и JavaScript без копирования, обычно через SharedArrayBuffer или прямое использование указателей в линейной памяти.
