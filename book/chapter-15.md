# Глава 15. C/C++ → WebAssembly

Emscripten — это самый полный инструментарий для компиляции C и C++ в WebAssembly . Он использует LLVM и Binaryen для трансляции кода и предоставляет эмуляцию стандартной библиотеки C, файловой системы и других функций операционной системы, которые обычно ожидают C-программы . Emscripten позволяет запускать существующие C/C++-приложения в браузере, Node.js и WASM-рантаймах, обеспечивая поддержку таких переносимых API, как OpenGL и SDL2, что делает возможным портирование сложных графических приложений, включая игровой движок Unity и Google Earth .

В этой главе мы рассмотрим ключевые аспекты компиляции C/C++ в WebAssembly с помощью Emscripten: от базового рабочего процесса до портирования игровых движков, эмуляции POSIX-системы и управления памятью в многопоточной среде.

## Emscripten и его возможности

Emscripten представляет собой полноценный компиляторный тулчейн, который транслирует C и C++ код в высокопроизводительный WebAssembly и JavaScript . Он предоставляет веб-поддержку для популярных переносимых API, таких как OpenGL и SDL2, позволяя портировать сложные нативные приложения .

### Среда и настройка

Для работы с Emscripten необходимо установить Emscripten SDK (emsdk), который включает компилятор `emcc` (аналог `gcc` или `clang`), инструменты линковки и системные библиотеки. После установки и активации окружения процесс компиляции сводится к вызову `emcc` с нужными флагами.

Базовый пример компиляции:

```bash
emcc -o hello.html hello.c
```

Эта команда генерирует три файла:
- `hello.wasm` — скомпилированный WebAssembly-модуль;
- `hello.js` — JavaScript-код (глю-код), отвечающий за загрузку и инстанцирование WASM-модуля;
- `hello.html` — HTML-страница для запуска приложения в браузере .

Для генерации только JavaScript и WASM (без HTML) используется флаг `-o hello.js`:

```bash
emcc -o hello.js hello.c
```

### Поддержка браузеров

Начиная с Emscripten 6.0.0, минимальные версии браузеров, поддерживаемые сгенерированным кодом, были повышены :
- Chrome 85+
- Firefox 79+
- Safari 14.1+

Это позволяет полагаться на такие возможности, как `mutable-globals` и `sign-ext`, без необходимости транспиляции через Babel .

### Интеграция с другими языками

Хотя Emscripten в первую очередь ориентирован на компиляцию C и C++ с использованием Clang, он может интегрироваться с другими компиляторами, использующими LLVM. Например, Rust имеет интеграцию с Emscripten через целевые платформы `wasm32-unknown-emscripten` и `asmjs-unknown-emscripten` .

### Лицензирование

Emscripten доступен под двумя пермиссивными лицензиями: MIT и University of Illinois/NCSA Open Source License . На практике это означает, что вы можете использовать Emscripten для любых целей — коммерческих и некоммерческих .

## Портирование игровых движков

Одно из самых впечатляющих применений Emscripten — портирование игровых движков и сложных графических приложений в веб. Unity была одной из первых крупных компаний, которая объявила о поддержке WebAssembly через Emscripten, ускоряя производительность игр в браузере .

### Примеры успешных портов

- **Unity Engine** — полноценный игровой движок, экспортирующий игры в WebAssembly через Emscripten .
- **Google Earth** — сложное геопространственное приложение, портированное в браузер с помощью Emscripten .
- **Библиотеки и фреймворки**: OpenGL ES 2.0, ImGui, PyQt, .NET Blazor .
- **Эмуляторы и утилиты**: классические эмуляторы, инструменты обработки изображений .

Ключевой фактор успеха — Emscripten обеспечивает веб-поддержку для OpenGL и SDL2, что позволяет графическим приложениям работать в браузере практически без изменений .

### Многопоточность в играх

Emscripten поддерживает многопоточность через два API: POSIX Threads (Pthreads) и Wasm Workers API .

**POSIX Threads (Pthreads)** ориентирован на переносимость и совместимость с нативными платформами. Если кодовая база компилируется для нескольких платформ (например, нативный Linux x64 и WebAssembly), Pthreads обеспечивает максимальную совместимость. Emscripten тщательно эмулирует поведение нативных Pthreads, что упрощает портирование больших C/C++-проектов .

**Wasm Workers API** предоставляет прямое отображение на веб-примитивы многопоточности. Если приложение разрабатывается только для WebAssembly и переносимость не является приоритетом, Wasm Workers даёт преимущества: более простой скомпилированный вывод, меньшую сложность, меньший размер кода и потенциально лучшую производительность .

### Поддержка SDL и графических API

Emscripten предоставляет эмуляцию SDL (Simple DirectMedia Layer) и OpenGL, что позволяет портировать игры, использующие эти API. Это включает поддержку:
- OpenGL ES 2.0/3.0 через WebGL;
- SDL1.2 и SDL2 через эмуляцию, работающую поверх веб-API;
- Ввода с клавиатуры, мыши и геймпада.

## Эмуляция POSIX

Emscripten эмулирует значительную часть POSIX API, что позволяет запускать существующие C/C++-приложения с минимальными изменениями. Однако существуют ограничения.

### Поддержка POSIX-функций

Emscripten предоставляет эмуляцию стандартной библиотеки C, файловой системы и других функций ОС . Однако полнота эмуляции ограничена :

- **Файловая система** — полностью эмулируется через виртуальную файловую систему, поддерживающую синхронный доступ из нескольких потоков (WasmFS) и хранение в браузерном хранилище.
- **Сокеты** — поддерживаются через эмуляцию поверх WebSocket. Однако существуют известные проблемы. Например, `poll/select` с эмулированными POSIX-сокетами может блокироваться бесконечно в некоторых сценариях . Поддержка блокирующих операций была добавлена в версии 4.0.23, но остаются edge-кейсы.
- **Защита стека (Stack Smashing Protection, SSP)** — не поддерживается полностью. Emscripten не предоставляет библиотеку времени выполнения для поддержки SSP, что приводит к ошибкам линковки при компиляции объектных файлов с вставленными вызовами защиты стека .

### Потоки и синхронизация

Emscripten поддерживает:

- Атомарные операции: `emscripten_atomic_*`, GCC `__sync_*`, C11/C++11 Atomics ;
- Локальную память потоков (TLS) через ключевые слова `thread_local` (C++11), `_Thread_local` (C11) и `__thread` (GNU11) ;
- Идентификаторы потоков: `pthread_self()` для Pthreads, `emscripten_wasm_worker_self_id()` для Wasm Workers .

**Ключевые различия между Pthreads и Wasm Workers** :

| Характеристика | Pthreads | Wasm Workers |
|----------------|----------|--------------|
| Проксирование JS-функций | Встроенная поддержка | Требуется ручная реализация |
| Точки отмены (cancellation) | Поддерживаются | Отсутствуют |
| Старт | Синхронный (пул воркеров) | Всегда асинхронный |
| Топология | Плоская (только главный поток создаёт потоки) | Иерархическая (воркер может создавать дочерние воркеры) |
| Завершение | При выходе из функции-точки входа | Только по явному вызову |
| Очередь прокси-сообщений | Есть (на поток) | Отсутствует |

**Проксирование JS-функций**. Только Pthreads могут использовать функции `MAIN_THREAD_EM_ASM*()` и директиву проксирования в JS-библиотеках. Wasm Workers не предоставляют встроенного проксирования; его нужно реализовать вручную через `emscripten_wasm_worker_post_function_*` .

**Старт и завершение**. Pthreads используют кешированный пул Worker'ов для ускорения синхронного старта. Wasm Workers стартуют асинхронно и выполняют функции, отправленные через `postMessage`, возвращаясь в цикл событий после завершения. Wasm Worker завершается только при явном вызове `emscripten_terminate_wasm_worker()` .

**Топология**. Pthreads "сплющивают" иерархию создания потоков, чтобы избежать проблем с вложенными Worker'ами в браузерах (например, Safari не поддерживает вложенные воркеры). Wasm Workers сохраняют иерархию .

### Ограничения POSIX-эмуляции

Некоторые POSIX-функции не поддерживаются полностью :
- Системные вызовы, зависящие от ОС и аппаратного доступа (например, некоторые операции с устройствами);
- Защита стека (SSP);
- Отдельные сетевые операции в сложных сценариях.

Поэтому при портировании кода на WebAssembly необходимо исключать неподдерживаемые вызовы API .

## Управление памятью в C/C++

Управление памятью — один из ключевых аспектов производительности C/C++-приложений в WebAssembly, особенно в многопоточных сценариях.

### Аллокаторы памяти

Emscripten по умолчанию использует `dlmalloc` — компактный, но эффективный аллокатор . Однако его многопоточная производительность ограничена: каждый вызов `malloc/free` блокирует глобальную блокировку, что приводит к серьёзным проблемам масштабируемости. В malloc-интенсивных бенчмарках производительность не только не растёт с добавлением ядер, но и ухудшается из-за длительного ожидания блокировки .

**Решение: mimalloc**. Для решения проблемы Emscripten интегрировал **mimalloc** — аллокатор от Microsoft, оптимизированный для многопоточности . Он используется следующим образом:

```bash
emcc -sMALLOC=mimalloc
```

Результаты впечатляют :
- Однопоточный malloc-бенчмарк: `dlmalloc` — 2660 мс, `mimalloc` — 1466 мс (ускорение ~2×).
- Многопоточный бенчмарк: производительность масштабируется линейно с добавлением ядер, тогда как с dlmalloc она деградирует.

`mimalloc` также даёт выигрыш в однопоточных приложениях, но увеличивает размер кода и потребление памяти, поэтому по умолчанию остаётся `dlmalloc` .

### Файловая система и I/O

До недавнего времени файловая система Emscripten (JS FS) была реализована на JavaScript и работала только на главном потоке. Остальные потоки проксировали запросы к главному потоку . Эта модель создавала проблемы в многопоточных приложениях:
1. Главный поток выполнял работу за другие потоки, вызывая пользовательскую задержку.
2. Фоновые потоки блокировались в ожидании главного потока.
3. Возникали дедлоки, если главный поток ожидал фоновый поток, который ожидал главный.

**Решение: WasmFS**. Новая файловая система **WasmFS** написана на C++ и компилируется в WebAssembly . Она хранит файлы в линейной памяти Wasm, общей для всех потоков, что позволяет выполнять файловый I/O из любого потока с одинаковой производительностью.

Результаты бенчмарков :
- На Pthread: WasmFS в **32 раза быстрее** JS FS.
- На главном потоке: WasmFS в **2 раза быстрее** JS FS.

WasmFS используется в production и считается стабильным . Он также поддерживает Origin Private File System (OPFS) для постоянного хранения. Рекомендуется использовать WasmFS, если только не требуется функциональность, которая ещё не перенесена .

```bash
emcc -sWASMFS
```

### Многопоточная память и SharedArrayBuffer

Emscripten поддерживает разделяемую память через SharedArrayBuffer. Для включения многопоточности необходимо:

1. Собрать с флагом `-pthread` (включает поддержку SharedArrayBuffer).
2. Настроить заголовки COOP/COEP для кросс-оригинальной изоляции.

В среде Wasm Workers, в отличие от Pthreads, отсутствует встроенное проксирование JS-функций, поэтому межпоточное взаимодействие требует ручной реализации через `emscripten_wasm_worker_post_function_*` и примитивы синхронизации из `<emscripten/wasm_worker.h>` (блокировки, семафоры, условные переменные) .
